# Email

## What this source contains

- Threads where something was requested, instructed, approved, or refused
- Attachments, which show the version that was actually sent
- Chains forwarded from outside: a client, a regulator, a vendor, a bank
- Cover notes that say what changed between two versions

Email is where instructions and approvals are most often on the record, with a sender and a date.

## How to search it

1. **Reference IDs and file names first.** Search for the ticket, matter, or invoice numbers from the anchor, and for the file name of the item as an attachment.
2. **Sender-bounded search.** Messages from the item's author or editor around the date it changed.
3. **Key terms**, inside a date window around the known changes. Try several phrasings.
4. **Read the whole thread**, including quoted earlier messages and every attachment.
5. **Compare attachments** across the thread when more than one version was sent.

## What good evidence looks like here

- An instruction or approval from the person with authority over the item
- A requirement stated by an outside party
- A cover note that explains the change it attaches
- A reply that rejects an alternative and says why

## Common pitfalls

- **One mailbox.** You see only the mailboxes you can search. Other people hold the rest. Name that as a gap.
- **Edited quotes.** Quoted text in a reply can be trimmed or changed. Cite the original message.
- **Forwarded summaries.** "Per the client" is a claim about what the client said. Find the client's own message before raising confidence.
- **Forked threads.** A reply to a subset of recipients starts a side thread. Search for both.
- **Automatic notifications** carry no motivation. Skip them.

## What to return

For each relevant message:
- Subject, sender, recipients, and date
- The key quotes (verbatim)
- Attachment names
- Link or message ID if available
